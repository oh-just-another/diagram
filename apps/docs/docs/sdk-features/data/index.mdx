A `Scene` is a plain, serialisable data structure. `@oh-just-another/serialization` turns it into a versioned JSON document and back, so you can store scenes anywhere — a file, a database, `localStorage`, or over the wire.

## Serialize and parse

`serializeScene` produces a `SceneDocument` (a stamped, schema-shaped object); `stringifyScene` is the JSON-string convenience. On the way back, `parseScene` validates against the wire schema and reconstructs a typed `Scene`.

```ts
import { emptyScene } from "@oh-just-another/scene";
import { serializeScene, stringifyScene, parseScene } from "@oh-just-another/serialization";

const scene = emptyScene();

const json = stringifyScene(scene, 2); // pretty-printed JSON string
const restored = parseScene(json);     // -> Scene
```

`parseScene` throws a `DeserializationError` on malformed or invalid input, so it doubles as a guardrail for untrusted JSON.

## Versioning and migrations

Documents are stamped with `CURRENT_VERSION` and validated against `SceneDocumentZ`. As the format evolves, register migrations so old documents upgrade on load instead of breaking:

```ts
import { registerMigration } from "@oh-just-another/serialization";

registerMigration({
  /* from / to version + an upgrade function */
} as never);
```

`runMigrations` applies the chain; a gap raises `MissingMigrationError`. The umbrella editor re-exports `registerMigration` so you can wire migrations from a single import.

## Binary file sidecars

Scenes that embed images keep large binary blobs in a `files` registry rather than inlining them into the scene JSON. `serializeFiles` / `stringifyFiles` / `parseFiles` persist that sidecar separately, producing a `SerializedFilesDocument` you can store alongside the scene (see Assets).

## With the editor

The `EditorAPI` handle exposes `getScene()` and `loadScene(scene)`, so a typical save/restore flow is `stringifyScene(api.getScene())` to persist and `api.loadScene(parseScene(json))` to restore. Loading a scene resets undo history.
